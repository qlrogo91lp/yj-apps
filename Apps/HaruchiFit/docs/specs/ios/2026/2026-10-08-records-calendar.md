# 03a 기록 — 달력

작성일: 2026-10-08
상태: **사용자 검토 완료 (2026-10-08)**. 기존 제품 스펙 03a절을 상세화한다.
사용자가 SwiftUI 월 그리드 방식을 확인하고 구현 플랜 작성을 요청했다.
구현은 별도 파일별 플랜 승인 후 진행한다.
수동 기록 추가·편집은 머지된 [PR #46](https://github.com/qlrogo91lp/yj-apps/pull/46)을 전제로 한다.

## 1. 목적과 범위

기록 탭에서 한 달의 운동 날짜와 운동량을 보고 개별 기록의 상세를 열어보는 화면이다.
홈은 최근 흐름, 통계는 연도별 집계, 기록 탭은 개별 기록 열람과 편집을 맡는다.

기존 확정 사항은 달력·목록 세그먼트 전환, 월 이동, 월 요약, 잔디와 같은 농도,
날짜 탭에서 기존 기록 상세 하프 시트로 이어지는 흐름이다.
기존 주 단위 목록·스와이프 삭제·상세의 부위/메모·수동 기록 편집은 유지한다.

달력에서 수동 기록을 새로 만드는 진입, 월별 차트, 목표, 연속 운동 배지,
HealthKit 추가 쿼리, 저장 모델 변경은 이번 범위에 포함하지 않는다.
수동 기록 생성은 기존 홈의 `+`를 사용한다.

## 2. 화면 구성

상단 제목은 `기록`이며 기존 다크 팔레트를 따른다. 콘텐츠 순서는 다음과 같다.

| 순서 | 영역 | 표시 내용 |
|---|---|---|
| 1 | 모드 전환 | `달력` · `목록` 세그먼트 |
| 2 | 월 이동 | `‹ 2026년 10월 ›`, 월 요약 `12회 · 9.2시간` |
| 3 | 요일과 월 그리드 | 7열, 날짜 숫자와 일별 농도 |
| 4 | 선택 날짜 | 날짜 제목, 해당 날짜의 기록 또는 빈 상태 |

목록 모드에서는 2~4 대신 기존 주 단위 목록을 표시한다.
모드 전환은 빈 상태에서도 표시한다.
달력 모드는 전체 콘텐츠를 하나의 세로 스크롤 영역으로 구성한다.
날짜별 기록은 중첩된 독립 List를 만들지 않고 아래로 이어 배치한다.
작은 화면과 큰 글씨에서도 월 그리드 아래 기록에 접근할 수 있어야 한다.

월 제목과 요약은 일반 크기에서는 같은 행에 둔다.
큰 글씨에서 공간이 부족하면 요약을 아래 줄로 내리며 숫자를 잘라 표시하지 않는다.

## 3. 초기 상태와 월 이동

앱 프로세스의 첫 진입은 `달력`, 현재 월, 오늘 선택이다. 첫 표시만으로 상세 시트를 열지 않는다.
모드·표시 월·선택 날짜는 탭을 오가도 유지한다. 프로세스 재시작 시 기본값으로 돌아간다.
목록으로 전환해도 달력의 월과 선택 날짜를 보존한다.

월 이동 버튼은 달력 연산으로 한 달씩 이동한다. 현재 월보다 미래로 이동할 수 없으며
현재 월에서는 다음 버튼을 비활성화한다. 과거 월은 기록 유무와 관계없이 이동할 수 있다.
월 이동으로 선택 날짜를 바꾸되 상세 시트를 자동으로 열지 않는다.

- 현재 월로 이동하면 오늘을 선택한다.
- 과거 월에서는 기록이 있는 가장 최근 날짜를 선택한다.
- 그 월에 기록이 없으면 1일을 선택한다.

앱 활성화 시 현재 날짜와 데이터를 다시 계산한다. 사용자가 보던 월·날짜를 유지한다.
날짜나 월이 넘어가도 자동으로 오늘로 이동하지 않는다.
재계산으로 이전의 미래 날짜가 오늘/과거가 되면 선택할 수 있게 한다.

## 4. 월 그리드와 날짜 경계

`Calendar.current`의 주 시작 요일을 따른다. 요일 라벨도 같은 순서로 표시한다.
주 단위로 왼쪽에서 오른쪽, 위에서 아래로 진행한다.
해당 월 첫날 앞에는 빈 자리를 두며, 마지막 주 끝까지 필요한 4~6행을 만든다.
월 밖 날짜는 숫자 없는 빈 자리로 두고 탭·VoiceOver 대상에서 제외한다.
윤년 2월과 주 시작 설정에 관계없이 해당 월의 날짜를 정확히 한 번씩 표시한다.

오늘은 고정 테두리로, 선택 날짜는 별도 외곽선과 선택 상태로 구분한다.
오늘이면서 선택된 날짜도 두 의미를 전달한다. 선택 표시가 농도 배경을 덮지 않는다.
미래 날짜는 빈 칸에 opacity 0.3을 적용하고 탭을 비활성화한다.
날짜 숫자는 농도에 관계없이 읽을 수 있는 대비를 확보한다.

모든 날짜 소속은 `startedAt`을 현재 달력/타임존으로 해석한다.
자정을 넘겨 끝난 기록은 시작한 날에 시간과 횟수 전부를 귀속한다.
워치·HealthKit import·수동 기록을 같은 규칙으로 포함한다.
현재 시각보다 미래에 시작하는 비정상 기록은 달력 집계와 날짜별 목록에서 제외한다.

## 5. 농도와 월 요약

농도는 기존 `GrassAggregator`와 `GrassIntensity.byTime`을 사용한다.
여러 기록의 `totalSeconds`를 하루 단위로 합산하고, 시간이 0이어도 기록이 있으면 최소 농도다.
기록이 없으면 빈 칸이다. 시간 기준 30·60·90분 컷과 팔레트는 홈·통계와 같다.
수동 기록도 입력한 운동 시간을 그대로 사용하며 소스를 이유로 최소 농도에 고정하지 않는다.
추후 설정에서 농도 기준을 바꾸면 홈·통계와 같은 기준을 전달받는다.
이번 작업에서 칼로리 컷이나 기준 전환 UI를 새로 만들지 않는다.

월 요약은 선택한 월 시작 이상·다음 월 시작 미만인 기록을 센다.
횟수는 운동한 날짜 수가 아닌 레코드 수다. 같은 날 두 기록이면 2회다.
시간은 그 월 `totalSeconds` 합계로, 1시간 미만은 정수 분,
1시간 이상은 소수 첫째 자리 시간으로 표시한다. 0건은 `0회 · 0분`이다.
현재 월은 현재 시각 이하에 시작한 기록만 포함한다.

## 6. 날짜 탭과 기록 상세

1개인 날은 날짜 탭으로 바로 상세를 열고, 여러 개인 날은 날짜 아래 목록에서 선택한다.
기존 03a의 바로 열기 동작을 살리면서 여러 기록을 임의로 하나만 열지 않는다.
모든 날짜에서 목록을 먼저 거치는 대안은 단일 기록에서도 상세 진입에 탭이 추가되어 채택하지 않는다.

날짜 탭은 선택 날짜를 갱신한다. 기록이 정확히 1개면 기존 `recordDetailSheet`로 연다.
2개 이상이면 자동으로 상세를 열지 않으며 날짜 아래 모든 기록을 최신 시작 시각 순으로 표시한다.
0개면 아래 빈 상태를 표시한다. 선택된 날짜를 다시 탭해도 같은 규칙으로 동작한다.

하단 제목은 `10월 8일 (목) · 2회`처럼 날짜와 횟수를 표시한다.
첫 진입·월 이동·동기화처럼 사용자가 날짜를 탭하지 않은 갱신에서는
기록이 1개여도 하단에 행을 보여주며 상세를 자동으로 열지 않는다.
상세를 닫은 뒤에도 선택 날짜와 해당 날짜의 행을 유지한다.

행은 기존 `RecordRow`의 세그먼트·부위·kcal 표기를 사용한다.
같은 날짜의 여러 기록을 구별할 수 있도록 시작 시각을 추가로 표시한다.
값이 없는 kcal는 기존 행 규칙을 따른다. 행 탭은 기존 상세 하프 시트를 연다.
달력 하단 행의 삭제는 상세의 삭제 액션으로 제공한다.
목록 모드의 기존 스와이프 삭제는 유지한다.

## 7. 빈 상태와 갱신

기록이 전혀 없어도 모드 전환·현재 월·빈 그리드·0값 월 요약을 표시한다.
그 아래 `아직 기록이 없어요`와 `워치에서 운동하거나 홈의 + 버튼으로 기록해 보세요.`를 표시한다.
다른 달에는 기록이 있지만 선택 월에 없으면 `이 달에는 기록이 없어요`를 표시한다.
선택 월에 기록은 있으나 선택 날짜에 없으면 `이 날에는 기록이 없어요`를 표시한다.
빈 날짜 선택만으로 수동 기록 폼을 열거나 기록을 생성하지 않는다.

워치 저장·import·수동 기록 추가/편집·삭제가 저장되면 표시 월과 선택 날짜를 유지하고
농도·월 요약·날짜별 행·기존 주 단위 목록을 갱신한다.
삭제로 선택 날짜의 마지막 기록이 사라져도 다른 날로 자동 이동하지 않는다.
수동 기록을 다른 날짜로 옮겨도 기존 선택 날짜를 유지하고 그 날짜의 현재 결과를 표시한다.
이전 날짜와 새 날짜, 서로 다른 월로 이동했을 때 두 월의 집계가 다음 열람에 정확해야 한다.

수동 편집은 영속 ID를 유지하는 제자리 변경이므로 `@Query` 배열 동일성만으로 갱신하지 않는다.
시작 시각·시간·세그먼트·부위 등 표시 입력의 값 변화와 기존 상세/편집 완료 콜백을 사용한다.
다른 탭에서 수정한 기록도 기록 탭 재진입 시 갱신한다.
상세의 삭제는 기존처럼 시트가 완전히 내려간 뒤 수행하고 삭제된 모델을 다시 읽지 않는다.
메모 초안 보존과 상세→수동 편집 전환은 #46의 기존 경로를 따른다.

당겨서 새로고침은 두 모드 모두 기존 `WorkoutSyncCoordinator.sync()`를 호출한다.
동기화 실패는 기존 앱 전역 알림으로 안내하며 저장된 기록과 현재 월·날짜 선택은 유지한다.

## 8. 구현 경계와 접근성

월 배치·날짜별 기록 분류·월 요약은 Foundation 기반 순수 모델/빌더로 둔다.
입력은 records·표시 월·now·calendar이며 날짜 경계와 현재 시각을 테스트에서 주입한다.
잔디 농도 규칙을 달력 빌더에서 다시 정의하지 않는다.

Records Feature의 ViewModel이 모드·월·선택 날짜와 표시 결과를 소유한다.
View는 SwiftData 입력과 앱 활성화를 전달하고, 컴포넌트는 값과 콜백만 받는다.
월 그리드는 SwiftUI `LazyVGrid`의 7열로 직접 구성하며 외부 달력 라이브러리를 추가하지 않는다.
Ralli의 전환·월 이동 패턴은 참고하되 테니스 모델/서비스를 HaruchiFit에 연결하지 않는다.
파일 목록과 타입명은 구현 플랜에서 확정한다.

모드와 날짜 선택은 VoiceOver에 선택 상태를 전달한다.
날짜는 `2026년 10월 8일, 운동 2회, 90분`처럼 날짜·횟수·시간을 읽는다.
오늘이면 `오늘`을 함께 읽으며 빈 과거 날짜도 날짜와 `운동 기록 없음`을 전달한다.
미래 날짜는 정보로 읽을 수 있지만 선택 불가 상태를 알린다.
월 이동 버튼은 `이전 달`·`다음 달` 접근성 이름과 비활성 상태를 갖는다.
날짜와 버튼은 최소 44pt 탭 영역을 확보한다.
큰 글씨에서는 날짜 그리드 열 수를 유지하고 행 높이를 늘리며 월 요약·기록 행은 줄바꿈한다.

## 9. 검증 기준

- 첫 진입: 현재 월·오늘·달력 모드이며 상세는 자동으로 열리지 않는다.
- 모드·탭 전환: 달력 선택을 유지하고 기존 주 단위 목록·삭제가 동작한다.
- 0/1/여러 기록 날짜: 명시한 빈 상태·직접 상세·기록 선택 흐름이 동작한다.
- 같은 날 2세션: 농도는 합산 한 칸, 월 요약은 2회이며 시작 시각으로 행을 구별한다.
- 29/30/31일·윤년·주 시작 변경: 모든 날짜가 정확히 한 번씩 배치된다.
- 월말·연말을 넘긴 운동: 시작 날짜/월에 전체 시간이 귀속된다.
- 현재 월 다음 버튼·미래 날짜·미래 시작 기록: 정해진 탐색 및 집계 제한을 따른다.
- 0초·30/60/90분·수동 기록: 홈·통계와 같은 농도가 나온다.
- 수동 기록의 날짜/시간/유형 편집: ID가 같아도 이전/새 날짜·월 요약·행이 갱신된다.
- 마지막 기록 삭제·삭제 실패·편집 실패: 선택 유지, 안전한 시트 전환, 기존 오류/초안 경로가 동작한다.
- 빈 전체 기록·빈 월·빈 선택 날짜: 서로 맞는 안내와 0값 요약을 표시한다.
- 자정/월 변경 후 활성화·다른 탭 편집·동기화: 날짜와 데이터는 갱신하되 선택을 유지한다.
- 작은 화면·Dynamic Type·VoiceOver: 날짜/시간 구분, 농도 대비, 스크롤, 탭 영역을 확인한다.
