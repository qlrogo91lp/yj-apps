# 워치 운동 종료 중복 요청 방지

- 플랜: [운동 종료 중복 요청 방지](../../plans/watch/2026/2026-11-04-workout-end-reentrancy.md)
- 브랜치: `fix/haruchi-workout-end-reentrancy`
- 상태: 구현·자동 검증·독립 코드 리뷰 완료. 실기기/UI 확인 대기.

## 원인과 확인 범위

첫 종료 요청이 HealthKit 마무리를 기다리는 동안 종료 버튼이 계속 활성화되어 추가 요청을 받을 수 있었다.
서비스는 첫 대기 전에 세션 참조를 비우므로, 두 번째 종료는 nil을 반환한다. 이 nil이 시작 화면으로
돌려보낸 뒤 첫 요청 완료가 결과 화면으로 전환하는 순서를 재현했다.

한 번의 터치가 두 요청을 발생시킨다는 증거는 없다. 사용자가 관찰한 실제 현상이 이 경로였는지는
실기기 입력·단계 로그 없이 확정할 수 없다. 이번 수정은 확인된 재진입 취약점을 막는다.

## 변경

- MainActor에서 첫 await와 구간 닫기 전에 `isEnding`을 설정한다. 중복 종료와 요약 이후 종료는 아무 상태도 변경하지 않는다.
- 종료 중 시작·유형 선택/전환·정지/재개를 막고, pause 신호가 종료 중 스냅샷을 새로 발행하지 않게 한다.
- 운동 화면 전체를 비활성화하고 접근성 탐색에서 숨기며, 불투명한 배경에 「운동 종료 중… / Ending workout…」 진행 표시를 띄운다.
- 종료 호출만 클로저로 주입해 실제 HealthKit 권한이나 저장 없이 완료 시점을 통제한다.
- 구간과 총 시간은 최초 요청 시점에서 고정한다. YJKit의 HealthKit 종료 순서와 저장/버리기 정책은 유지한다.

```bash
  -destination id=03F797B3-B50B-4828-8F2F-C09BFD101B30 test
```

- RED: 종료 테스트 스위트에서 4개 실패, 1개 통과. 시작 조작 테스트 1개는 수정 전 실제 권한 요청을 피하려고 이 실행에서만 비활성화했다.
- GREEN: 6개 신규 테스트를 모두 활성화해 전체 **199개 통과, 실패·스킵 0개**.
- 검사: `swiftlint` 104개 파일 위반 0개, `swiftformat --lint .` 142개 파일 수정 필요 0개, `git diff --check` 통과.
- 테스트는 초기 idle 상태의 뷰모델에 종료 대역을 주입한다. 실제 세션 시작/종료와 active 상태의 pause 콜백 연결 검증을 대체하지 않는다.

## 코드 리뷰

독립 리뷰에서 Critical/Important 결함은 없었다. 다음 테스트 한계는 Minor로 기록했다.

- pause 스냅샷 테스트는 idle 상태이므로 `!isEnding` 조건 자체의 회귀를 검출하지 못한다.
- `togglePause` 테스트의 세션은 시작되지 않아 서비스 자체가 no-op이다. 실제 active 상태의 호출 차단은 수동 확인이 남는다.
- 기존 권한 요청을 기다리던 `start()`와 외부에서 호출한 `end()`의 경합은 현재 UI에서 재현 경로가 확인되지 않은 기존 문제로 범위에 추가하지 않았다.
- HealthKit 오류·타임아웃 복구는 승인된 플랜처럼 별도 작업이다.
