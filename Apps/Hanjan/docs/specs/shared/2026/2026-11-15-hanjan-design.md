# 한잔 (Hanjan) — 설계

Linear: YJ-42 (본건) · YJ-43 (추후 아이디어)

## 왜 만드는가

주량이 다른 친구와 같은 속도로 마시다 먼저 취한다. 술자리에서 **내가 지금 몇 잔째인지, 한도까지 얼마나 남았는지**를
손목에서 바로 보고 싶다. 사용자는 사실상 본인 한 명, 대상은 한국.

기본은 **내가 마신 잔만 세는 카운터**다. 처음 아이디어였던 "친구와 짠은 같이 하되 나는 몇 번에 한 번만 마신다" 는
술자리 중에 켜는 **짠 모드**로 넣는다 — 혼자 마시거나 짠 없이 마실 때는 끄고 쓴다.

## 목표 · 비목표 · 반목표

**목표**
- 취한 상태에서도 쓸 수 있을 만큼 단순하다. 진행 중 화면의 조작은 `한 잔` 과 `취소` 둘뿐
- 워치와 폰 어느 쪽에서 눌러도 같은 숫자가 된다. 연결이 끊겼다 붙어도 잔이 빠지거나 두 번 세지지 않는다
- 이번 주 안에 TestFlight 시운영 + App Store 심사 **제출** (승인은 기다리지 않는다)

**비목표** (이번 버전에서 하지 않는다 — YJ-43)
- 시간 페이스 경고, 1차/2차 구분, "3번 중 2번" 같은 복합 비율, 반 잔 단위 입력
- 기록 기반 한도 자동 추정 (이번에는 데이터만 모은다)
- 사진, 영수증 OCR, 술값 정산, 술게임
- 디지털 크라운 조작, 손가락 더블 탭, 짠 제스처 인식
- 혈중알코올농도 추정. 의학적 정확도를 내세우지 않는다

**반목표**
- 음주를 부추기는 표현·기능 (심사 반려 사유이자 앱 취지와 반대)
- 설정·입력이 늘어나 술자리에서 쓰기 번거로워지는 것

## 제약

- 운동 앱이 아니다. `WorkoutCore` · HealthKit 을 쓰지 않는다. 따라서 워치 화면이 꺼진 뒤에는 시계 화면으로
  돌아간다 → **컴플리케이션이 진입로**다
- 서버가 없다. 알림은 전부 로컬 알림. Live Activity 는 폰 앱이 화면에 떠 있을 때만 시작할 수 있다
- 저장 모델은 처음부터 CloudKit 제약을 지킨다 (모든 속성에 기본값 또는 옵셔널, unique 제약 없음)
- 권한은 알림 · 위치(사용 중) 둘뿐. 거부해도 나머지는 동작한다
- 모노레포 규약(`CLAUDE.md`, `docs/specs/2026/2026-09-03-xcode-target-conventions.md`)을 따른다

## 접근 방식

폰과 워치 중 누가 기록의 원본인가를 두고 셋을 비교했다.

| 안 | 내용 | 판단 |
|---|---|---|
| A. 폰이 원본, 워치는 리모컨 | 워치는 "추가" 명령만 보내고 폰이 계산한 결과를 받는다 | 가장 단순하나 연결이 끊기면 워치 숫자가 멈추거나 어긋난다 |
| **B. 잔 하나 = 고유 ID 기록** | 양쪽이 각자 기록을 쌓고 서로 보낸다. 같은 ID 는 한 번만 센다 | **채택.** 끊겨도 양쪽에서 입력되고 다시 붙으면 합쳐진다 |
| C. 양쪽 다 iCloud 직접 저장 | 동기화 코드가 거의 없다 | 반영이 수 초~수 분이라 실시간이 안 된다 |

사용자가 B 를 골랐다 — 화장실에 다녀오는 등 술자리에서 폰과 워치가 떨어지는 일이 실제로 있다.

## 동작

### 세션
- 술자리 1회 = 세션. 대기 화면의 `시작` 으로 연다. 시작 시 그 기기가 위치를 한 번 받는다
- 종료는 수동, 또는 마지막 입력 후 3시간이 지나면 자동
- 동시에 열린 세션은 하나

### 한 잔
- `한 잔` = 기록 하나 추가: `id(UUID) · 세션 id · 술 종류 · 시각 · 입력 기기 · 짠만 여부`
- `취소` = **가장 최근 기록 하나를 삭제** (술 종류 무관). 삭제도 ID 로 전파한다. 첫 잔 전에는 비활성
- 취소 직후 "소주 1잔 취소됨" 을 잠깐 보인다
- 술 종류는 세션 중 언제든 바꿀 수 있다. 바꾼 뒤의 `한 잔` 부터 적용

### 짠 모드
- 끔 / 2번 중 1번 / 3번 중 1번. 세션은 항상 끔으로 시작하고, **진행 중 입력 화면에서 `짠` 캡슐을 눌러** 켠다 (누를 때마다 끔 → 2번 중 1번 → 3번 중 1번 → 끔). 시작 화면에는 선택이 없다
- 켜거나 비율을 바꾸면 그 순간부터 점이 1번부터 다시 센다. 끄면 버튼은 항상 `한 잔`. 폰과 워치 중 나중에 바꾼 설정이 양쪽에 적용된다
- 켜면 짠할 때마다 주 버튼을 한 번 누른다. 숫자 옆의 **원형 점**이 한 번에 하나씩 차고, **점이 다 찬 차례에만 마신다**
- 버튼은 자리와 크기가 그대로이고 글자와 모양만 바뀐다: 마실 차례 `한 잔`(앰버 채움), 아니면 `짠만`(테두리만)
- `짠만` 을 누르면 잔 수는 그대로고 차례만 넘어간다. 직후 "짠만 했어요" 를 잠깐 보인다
- `취소` 는 `짠만` 이든 `한 잔` 이든 방금 누른 것 하나를 되돌리고 차례도 한 칸 돌아간다
- 한도·통계·술별 잔 수는 실제 마신 잔만 센다. 기록 상세에는 "짠만 8번" 을 보인다
- 짠 사이에 따로 마신 잔을 넣는 방법은 두지 않는다 (누르면 차례가 넘어간다). 정확도보다 단순함을 택했다

### 단위
- 술 종류마다 `도수(%)` · `한 잔 용량(ml)` 을 갖는다. 기록은 순수 알코올 g 으로 합산한다
- 화면에는 g 이 아니라 **소주 환산 잔 수**로 보인다 (기준: 소주 1잔)
- 기본 프리셋: 소주 · 맥주 · 소맥 · 와인 · 위스키 · 기타. 사용자가 추가·편집할 수 있다 (폰에서만. 워치는 고르기만)
- 프리셋의 도수·용량 수치는 구현 때 정한다. 정밀할 필요는 없다

### 한도
- 첫 실행 온보딩에서 "평소 주량 소주 몇 잔" 을 받아 한도로 쓴다. 설정에서 고친다
- 80% · 100% 도달 시 로컬 알림 + 워치 햅틱. 100% 를 넘으면 숫자·막대·버튼이 빨강
- 한도를 넘어도 입력은 막지 않는다

### 다음 날 회고
- 세션이 끝나면 다음 날 오전 로컬 알림을 예약한다 → "어제 어땠나요?"
- 상태 5단계 (글자, 이모지 없음): 멀쩡 / 기분 좋음 / 취함 / 많이 취함 / 필름 끊김
- 함께한 사람(한 번 입력한 이름은 다음부터 고르기), 장소 이름(위치에서 자동 입력, 수정 가능), 메모
- 모두 선택 입력. 기록 상세에서 나중에 고칠 수 있고, 잔 수도 술별 스테퍼로 고칠 수 있다

### 기록 · 통계
- 기록 탭: `목록 | 캘린더` 전환. 캘린더는 마신 날 앰버 점, 한도 넘긴 날 빨간 점. 날짜를 고르면 그날 요약
  (Ralli 캘린더 구현을 참고)
- 상세: 지도(MapKit), 소주 환산 잔 수, 술별 잔 수, 상태, 함께한 사람, 메모
- 홈 "이번 달" 카드: 술자리 횟수 · 총 잔 수(소주 환산) · 한도 넘긴 횟수

## 화면

**워치** — 시작 / 진행 중(가로 2페이지: 입력 · 경과 시간/시작 시각/술별 잔 수와 `종료`) / 한도 초과 / 술 선택 / 종료 확인.
입력 페이지에는 종료 버튼을 두지 않는다 — 잘못 눌러 세션이 끝나는 것을 막는다. 아래 페이지 점으로 옆 화면이 있음을 알린다

```
┌────────────────┐
│ 소주 ⌄         │
│     5 / 8잔    │
│ ▓▓▓▓▓░░░       │
│ [취소][  한 잔 ]│   폭 약 1:3. 취소는 회색 테두리, 한 잔은 앰버 채움
└────────────────┘   라벨은 글자만 (+, −, 아이콘, 이모지 없음)

짠 모드: 입력 화면 맨 위 줄 왼쪽에 술 종류 캡슐, 오른쪽 끝에 `짠` 캡슐(켜면 앰버). 켜면 숫자 옆에 원형 점, 주 버튼이 `한 잔` / `짠만`. 폰은 술 선택 칩 줄의 오른쪽 끝
```

**iPhone** — 탭: 홈 / 기록 / 설정
- 온보딩 4장: ① 주량 입력 ② 폰과 워치 어디서든 (어느 쪽에서 눌러도 같이 올라간다, 폰만으로도 쓸 수 있다) ③ 짠 모드 ("친구와 속도가 달라도 괜찮아요" — 점이 다 차면 마실 차례) ④ 알림·위치 권한과 이유
- 홈 대기: 한도, `시작`, 이번 달 카드, 최근 기록
- 홈 진행 중: 경과 시간과 시작 시각(시작 시각에서 계산, 분 단위), 5 / 8 + 막대, 술별 잔 수, 술 선택 칩(+ 더보기 시트), `취소` `한 잔`, 종료
- 기록 목록 · 캘린더 · 상세 · 잔 수 편집 · 다음 날 입력
- 설정: 한도, 술 목록 추가·편집(이름 · 도수 · 용량 · 소주 환산 미리보기), 알림

**컴플리케이션** — 세션 없음: 아이콘만 / 진행 중: `5/8` + 진행 링. 원형 · 코너 · 직사각형

**Live Activity** — 잠금화면 배너(5 / 8잔 + 막대 + `한 잔` 버튼), 다이내믹 아일랜드 컴팩트·확장, 한도 초과는 빨강.
`한 잔` 버튼은 일정이 밀리면 가장 먼저 뺀다

**디자인** — 어두운 배경 + 메인 색 앰버(시안 A안). 경고만 빨강. 버튼 스타일은 Ralli 를 따른다 (주 버튼은 시스템 강조 버튼에 앰버, 보조 버튼은 얇은 테두리 캡슐). 아이콘은 앰버 액체가 반쯤 찬 소주잔 실루엣
(두꺼운 바닥 + 하단 세로 커팅, 시안 변형 a). 디자인 원본은 FigCraft 문서 `~/Workspace/Projects/figcraft/hanjan/Hanjan.figcraft`
하나로 관리한다. git 에 넣지 않고 결과물(아이콘·이미지)만 이 저장소로 가져온다

HTML 시안(웹 목업)은 논의용 임시 산출물이다 (`~/Workspace/Projects/figcraft/hanjan/mockup/`). FigCraft 문서로 옮긴 뒤에는 그쪽이 원본이다.

## 구조

- 위치 `Apps/Hanjan/`, 폴더 구성은 HaruchiFit 을 따른다 (`iOSApp` / `WatchApp` / `Shared` / `ComplicationApp` + Live Activity)
- 타깃 4개: iOS 앱 · Watch 앱 · 컴플리케이션 확장 · Live Activity 확장. 이름과 번들 ID 는 타깃 규약 문서 §1
- YJKit: `ConnectivityCore`(양쪽), `PersistenceCore`(iOS). `WorkoutCore` · `WorkoutUI` 는 링크하지 않는다
- 루트 `Makefile` 의 `APPS`, `YJApps.xcworkspace`, 루트 `CLAUDE.md` 의 구조·스킴 목록에 앱을 추가한다

**동기화 (B안)**
- 메시지: 세션 시작 / 세션 종료 / 잔 추가 / 잔 삭제 / 술 종류 목록 · 한도(폰→워치). 전부 ID 기반이라 여러 번 받아도 결과가 같다
- 전송은 `ConnectivityCore` 의 큐잉(reliable) 경로. 도착 순서에 기대지 않는다 — 삭제가 추가보다 먼저 와도 맞아야 한다
- 화면의 잔 수는 저장된 숫자가 아니라 **기록 목록에서 계산한 값**이다
- 폰이 최종 보관(SwiftData + CloudKit). 워치는 진행 중 세션만 로컬에 갖고, 종료가 폰에 전달된 뒤 비운다
- 워치 → 컴플리케이션은 App Group 으로 현재 숫자를 넘기고 타임라인을 갱신한다
- 폰은 워치 메시지를 받으면 백그라운드에서도 Live Activity 와 한도 알림을 갱신한다

**저장 모델 (iOS)** — 세션(시작·종료 시각, 좌표, 장소 이름, 상태, 메모, 세션 당시 한도) · 잔 기록 · 술 종류 · 함께한 사람

## 빌더에게 맡기는 것

- 프리셋 술의 도수·용량 수치, 알림 문구, 다음 날 알림 시각
- 메시지 타입의 구체 필드와 워치 로컬 저장 방식
- Ralli 캘린더·Live Activity 코드를 복사할지 공용으로 올릴지 (이번 주는 복사가 기본)
- 최소 OS 버전 (기존 앱과 맞춘다)
- 테스트 범위: 최소한 동기화 병합(중복 수신 · 순서 뒤바뀜 · 끊김 후 재연결)과 소주 환산 계산
