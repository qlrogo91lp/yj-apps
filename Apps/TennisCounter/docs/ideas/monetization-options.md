# Ralli 수익화 방안 탐색

- 작성일: 2026-10-27
- 상태: **보류** — 다운로드가 1,000 미만이라 지금 파는 건 위험하다. 기능 구현이 먼저이고, 이 문서는 나중에
  꺼내 볼 수익원 목록으로 남긴다
- 동기: 클럽 기능(서버)이 들어오면 운영비가 생기고, 이참에 수익도 내 보고 싶다. 돈을 낼 수 있는 길을
  **전부** 늘어놓고 무엇을 언제 붙일지 정한다.
- 선행 문서
  - [클럽 대진표 · 실시간 중계 탐색](club-live-scoring.md) — 백엔드·단위·기록자·게스트·레이팅 결정
  - [Ralli 업데이트 로드맵](ralli-update-roadmap.md) "수익화 전략" 절 — 이 문서가 그 절을 대체한다

## 한 줄 요약

**동호회 기능은 전부 무료로 퍼뜨리고, 돈은 폰 화면 광고와 "워치가 자동으로 모은 데이터"의 분석에서 받는다.**
**단 지금은 보류 — 기능 구현과 서버비 최소화가 먼저다.**

## 지금의 결정 (2026-10-27)

- **수익화 보류.** 다운로드 1,000 미만에서 결제·광고를 붙이면 사용자를 모으기 전에 막는다
- **서버 운영비 최소화가 기준** — Spark(무료) 요금제로 시작, 건강 데이터는 서버에 올리지 않음, 경기당 쓰기
  최소화. 상세는 [클럽 탐색 문서 "서버비 최소화 원칙"](club-live-scoring.md#서버비-최소화-원칙-2026-10-27)
- **다시 꺼낼 시점** *(제안)*: ① 클럽 기능 출시 뒤 활성 동호회가 생기고 사용 데이터가 쌓였을 때
  ② Firebase 무료 한도에 닿아 Blaze 전환이 필요해질 때 — 운영비가 실제로 생기는 순간
- 보류 중에도 기능으로서 가치가 있어 먼저 해도 되는 것: **첫 서브 설정**(워치 서브 표시), **포인트 이벤트 로그**
  (확정 결과에 담기 — 서버비 원칙 3). 둘 다 나중 Pro 분석의 바탕이 된다

## 원칙

1. **동호회 쪽은 무료** — 클럽 생성·가입·대진·랭킹·기록. 무료 대체재가 이미 있고(아래 "시장"),
   랭킹은 멤버 전원이 들어와야 의미가 있다. 입구에서 돈을 받으면 퍼지지 않는다
2. **이미 무료로 준 것은 잠그지 않는다** — 지금 Ralli 는 경기 기록을 기간 제한 없이 무료로 저장·표시한다.
   유료는 **새로 만드는 가치**에만 붙인다
3. **워치와 경기 중 화면에는 광고가 없다** — 경기 경험이 Ralli 의 본체다
4. **기대치는 부업 수준** *(추정)* — 돈을 낼 수 있는 사람이 "아이폰 + 애플워치를 쓰는 테니스 동호인"으로 좁다.
   서버비를 덮는 건 쉽고, 큰돈은 사용자 수가 한 자릿수 이상 늘어야 한다

## 방안별 메모

### 팁 (1·2·14)

- **앱 안의 개발자 팁은 인앱 결제로 해야 한다** (가이드라인 3.1.1 — "앱은 인앱 결제 화폐로 개발자에게 '팁'을
  줄 수 있다"). 외부 Buy Me a Coffee 링크는 앱 소개 화면에만 넣어도 3.1.1 로 거절된 사례가 있다.
  미국 스토어프런트는 2025-04 판결 뒤로 외부 링크가 허용됐지만, 심사가 일관되지 않다는 보고가 있다
- 형태: 소모성 상품 3종 (예: ₩1,100 / ₩3,300 / ₩5,500 — "커피 한 잔 / 두 잔 / 한 판")
- Buy Me a Coffee 는 **앱 밖**에 둔다 — 보기 전용 웹, 인스타, 블로그. 안드로이드 멤버도 낼 수 있다
- 전환을 올리는 장치: 동호회 화면의 **후원자 배지**(꾸미기만, 기능 해금 없음), 시즌 결산이나 첫 승리 같은
  기분 좋은 순간에 한 번만 묻기. 반복해서 조르지 않는다

### 광고 (3·4·5·6·13)

- **언제:** 클럽 A 단계(대진·결과 반영)가 나간 뒤. 지금은 폰을 열 이유가 기록 확인 정도라 노출이 적다.
  [클럽 탐색 문서](club-live-scoring.md)의 동기 — "광고를 붙이려면 폰을 열 이유가 있어야 한다"와 같은 얘기다
- **어디에:** 모임·대진표 화면, 클럽 랭킹, 기록 목록 사이의 **네이티브 광고**(목록 카드처럼 생긴 것).
  배너는 차선
- **어디는 안 되나:** 워치(AdMob 은 watchOS 를 지원하지 않는다), 경기 중 폰 화면, Live Activity, 온보딩,
  결과 저장 직후 전면 광고
- **광고 제거(6)를 같이 판다** — 데이터를 가두지 않고도 "돈을 낼 이유"가 생긴다. Pro 가 생기면 Pro 에 포함한다
- 기술: Firebase 를 이미 쓰고 있어 **AdMob** 이 가장 짧다
- 심사·법무: 개인화 광고를 쓰면 **ATT 권한 요청**, 앱 개인정보 라벨에 광고 데이터 추가, 개인정보처리방침 갱신.
  글로벌 출시라 EEA·영국 사용자에게는 **Google UMP 동의 화면**이 필요하다. 비개인화 광고만 쓰면 ATT 는 생략할 수 있다
- 보기 전용 웹(13)에 AdSense 를 붙이면 안드로이드 멤버도 노출되지만 트래픽이 작아 후순위

### Pro 구독 (7) — 워치만 만들 수 있는 분석

| 묶음 | 보여 주는 것 | 필요한 데이터 | 지금 |
|---|---|---|---|
| ① 실력 추이 | Elo 그래프, 상대별 전적, 파트너 궁합, "오늘 이 상대에게 이길 확률" | 경기 결과 | 클럽 A 단계에서 생긴다. 경쟁 앱도 흉내 낼 수 있음 |
| ② 접전 분석 | 듀스 게임 승률, 타이브레이크 승률, 4:4 이후 승률, 리드 지키기·역전률 | 포인트 이벤트 로그 | 워치가 세지만 **저장 안 함** |
| ②+ 서브 지표 | 서브 게임 지키기율, 브레이크 성공률 (팀·개인) | 로그 + **첫 서브 설정** | 서브 개념 없음 |
| ③ 체력 분석 | 심박 흐름 위에 점수 흐름, 고심박 구간 포인트 승률, 세트 후반 승률 하락 | 로그 + 심박 시계열 | 심박 흐름은 **HealthKit 에 이미 있다** (워치가 워크아웃을 저장) — 기기에서 조회하면 된다 |
| ④ 스윙 분석 | 포핸드·백핸드·서브 횟수 | 모션 + 머신러닝 | 없음 — 보류 |

- **첫 서브 설정:** 경기 시작 전에 첫 서브 팀(탭 한 번)을 받는다. 복식은 팀별 첫 서버까지(두 번 더) 받으면
  개인 지표가 나온다 — 순서가 A1 → B1 → A2 → B2 로 고정이라 나머지는 계산된다. 세트가 바뀔 때 순서를 바꾸는
  경우는 드무니 수정만 열어 둔다. 덤으로 워치에 "이번 게임 서브: 상대 팀 B" 를 띄울 수 있다 — **이건 무료 기능**
- **데이터는 지금부터 무료로 쌓는다.** 새로 쌓을 것은 **포인트 로그뿐**이다 — 심박은 HealthKit 에 이미 있다.
  포인트 로그를 클럽 A 단계(또는 그 전)에 넣어 두면 Pro 를 여는 날 이미 몇 달 치가 있어 결제 직후부터 분석이
  풍성하다. 클럽 탐색 문서의 **이벤트 로그 점수 모델** 결정과 같은 구조를 쓴다
- **심박 흐름을 직접 저장하지 않는다** — 가이드라인 5.1.3(ii)("개인 건강 정보를 iCloud 에 저장하지 말 것")와
  서버비 원칙 둘 다에 걸린다. 분석 화면이 열릴 때 HealthKit 에서 경기 시각 구간을 조회한다
- 무료 맛보기: **가장 최근 경기의 분석 하나**는 무료. 기간 추이·전체 분석이 Pro
- 가격 *(가정)*: 월 ₩3,900 · 연 ₩29,000 전후. 로드맵의 $2.99~3.99/월과 같은 범위. 출시 직전 비슷한 앱으로 확정
- 구독이 평생 구매(8)보다 맞는 이유: 분석 대상 데이터가 계속 쌓이고 서버비도 계속 든다

### 제휴 + 장비 추적 (11)

- 라켓·스트링·신발을 등록하면 **워치가 센 플레이 시간이 장비별로 쌓인다** (Strava 의 신발 거리 추적과 같은 발상).
  "스트링 40시간 — 교체 시기" 알림 → 용품 링크
- 실물 상품은 인앱 결제 대상이 아니라 외부 링크가 허용된다 (가이드라인 3.1.3(e))
- 쿠팡 파트너스 같은 제휴 링크는 **수수료 표시 문구**가 의무다 (공정위 추천·보증 심사지침)
- 수수료율이 낮아 돈보다 "Ralli 가 아는 정보로 도움을 준다"는 경험 쪽 가치가 크다

### 지역 스폰서 (12)

- 클럽 랭킹 화면이나 시즌 결산 카드에 "이번 시즌 후원: ○○ 테니스장" 한 줄
- 동호회는 지역 기반이라 동네 테니스장·스트링샵·레슨 코치에게 정확한 타깃이다
- 영업이 필요해서 1인 개발로는 동호회가 수십 개 모인 뒤에나 현실적

## 수익 감 잡기 — 가정치 예시

**모든 숫자가 가정이다.** 실제 MAU·방문 빈도·eCPM 이 나오면 바꿔 넣는다. Apple 수수료는 소규모 사업자
프로그램 기준 15%.

월 활성 사용자(MAU) **1,000명**이라고 하면:

| 방안 | 가정 | 월 수령액 |
|---|---|---|
| 광고 | 1인 월 8회 방문 × 방문당 노출 2회 × eCPM ₩1,500 | ≈ ₩24,000 |
| 팁 | 월 0.5%가 평균 ₩3,300 | ≈ ₩14,000 |
| Pro 구독 | 2% 전환 × 월 ₩3,900 | ≈ ₩66,000 |
| 광고 제거 | 2%가 ₩4,400 한 번 | ≈ ₩75,000 (일회) |

- 비용: Firebase 는 이 규모에서 무료 한도 안(클럽 탐색 문서 "요금 구조"), 개발자 계정 연 $99
- 읽는 법: **1,000명에서는 운영비를 덮고 남는 정도.** 사람 수당 가장 큰 지렛대는 구독이고, 광고는 규모가 있어야 의미가 있다
- 측정 공백: 지금 Ralli 에는 Crashlytics 만 있고 사용량 분석이 없다. 광고·Pro 를 판단하려면 App Store Connect
  분석으로 시작하고, 부족하면 Firebase Analytics 를 검토한다

## 열린 질문

- 실제 MAU·방문 빈도 — 위 가정치를 갈아 끼울 숫자
- 광고 제거를 따로 팔지, Pro 에만 넣을지
- Pro 가격(원화·달러), 월간/연간 구성, 무료 체험 기간
- 후원자 배지를 둘지 — 동호회 화면에 남이 보는 표시라 반응이 갈릴 수 있다
- 개인화 광고(ATT 요청)까지 갈지, 비개인화만 쓸지
- 장비 추적을 Pro 에 넣을지 무료로 둘지
- CourtMate 가 유료 요금제를 갖고 있는지
