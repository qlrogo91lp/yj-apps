# iOS 온보딩 설계

2026-09-07 확정 · **2026-09-17 개정** (4페이지 → 5페이지, 워치 중심으로 재편).

## 목적

**사용자가 워치에서 기능을 최대한 쓰게 만든다.**

Ralli 는 워치로 점수를 넣는 앱이다. 그런데 워치에서 할 수 있는 일 중 화면에 힌트가 없는 것이 많다 —
크라운 회전, 좌우 스와이프로 가는 워크아웃 탭, 문자판 컴플리케이션. 이것들을 모르면 사용자는
앱의 절반만 쓴다. 온보딩은 그 간극을 메우는 자리다.

설득이 아니라 안내다. 3초 훑고 닫아도 "크라운으로 점수가 들어간다" 는 남아야 한다.

2페이지가 흡수한다. 남는 둘은 안내가 필요 없다: **되돌리기**는 점수 화면 하단에 버튼이 보이고,
**미러링**은 아무 조작 없이 저절로 동작한다. 화면에서 발견되는 것을 온보딩이 또 말할 이유가 없다.

영문은 플랜의 문자열 표에 있다.

**3페이지 제목에 "컴플리케이션" 을 넣지 않은 이유** — 사용자가 얻는 것(한 번 탭으로 진입)을 제목에
두고 용어는 본문에서 쓴다. 다만 본문에는 **"컴플리케이션"** 을 그대로 쓴다. 애플이 한국어 워치
설정에서 쓰는 공식 용어라, 문자판에서 찾을 때 같은 단어를 보게 된다.

**1~3 이 워치, 4~5 가 결과물**이라는 순서다. 워치로 무엇을 어떻게 하는지 먼저 익히고,
그것이 어디에 쌓이고 어떻게 나가는지로 끝낸다.

## 형식

- `TabView(.page)` 5장, 하단 페이지 인디케이터
- 1~4 페이지: 우상단 **건너뛰기**, 하단 **다음**
- 5 페이지: 하단 **시작하기** — 닫으면서 플래그 저장
- 건너뛰기도 플래그를 저장한다. 강제로 다시 보여주지 않는다
- 앱이 다크 고정(`TennisCounter-Info.plist` 의 `UIUserInterfaceStyle = Dark`)이라 온보딩도 검정 배경 +
  브랜드 색 버튼. `LaunchScreenView` 에서 이어지는 톤

## 노출 규칙 — "봤나" 가 아니라 "몇 번째까지 봤나"

개정 전과 같다.

```
OnboardingGate.version = 1          // 내용이 바뀌면 올린다
UserDefaults "onboardingSeenVersion" // 기본 0
표시 조건: seenVersion < version
닫을 때:  seenVersion = version
```

| 사용자 | 저장값 | 결과 |
|---|---|---|
| 새 설치 | 0 | 뜸 |
| 1.1.7 에서 업데이트 | 0 | **뜸** — 이번 출시의 새 기능(크라운·공유)을 봐야 할 사람이 기존 사용자다 |
| 이번 버전에서 봄 | 1 | 안 뜸 |
| 다음 출시에서 내용 수정 + `version = 2` | 1 | 다시 뜸 — What's New 역할 |

- **`version` 은 1 그대로 둔다.** 이번 개정은 아직 출시된 적 없는 온보딩을 고치는 것이라 올릴 이유가 없다
- 저장소는 `UserDefaults.standard`. iCloud 동기화 안 함 — 기기마다 한 번이 자연스럽다
- 삭제 후 재설치 → 0 → 다시 뜸. 정상
- 설정 페이지(작업 #8)의 "사용법 다시 보기" 는 같은 뷰를 재사용하되 플래그를 건드리지 않는다

## 진입 위치

`TennisCounterApp` — `LaunchScreenView` 가 끝난 직후, `MainTabView` 앞. 개정 전과 같다.

```
isLaunching → LaunchScreenView
    ↓
seenVersion < version → OnboardingView(onFinished: seenVersion = version)
    ↓
MainTabView
```

`MainTabView` 위에 시트로 띄우지 않는다 — 시트는 아래로 당겨 닫히고, 그러면 플래그가 안 남는다.

## 플랫폼 — iOS 만

워치엔 온보딩을 두지 않는다. 화면이 좁고, 워치 사용자는 거의 항상 폰 앱을 먼저 연다.
워치에서 안내할 것은 1~3 페이지가 폰에서 보여준다. 컴플리케이션으로 워치만 쓰고 폰 앱을
한 번도 안 연 사용자는 폰을 열 때 본다.

## 그림 — Figma 워치 목업에 합성

**워치 스크린샷은 시뮬레이터든 실기기든 화면만 찍힌다.** 베젤도 크라운도 그림에 없다. 그 상태로는
"크라운을 돌린다" 를 설명할 수 없고, 워치 화면이라는 것조차 잘 전달되지 않는다. 그래서 워치 3장은
**Figma 목업 프레임에 화면을 끼워** 만든다.

| 에셋 | 출처 | 만드는 방법 |
|---|---|---|
| `OnboardingCrown` | Figma `onboarding-crown` | 워치 목업 + 점수 화면. **세트 0:0** 이어야 "나"/"상대" 라벨이 보인다 (`hasSetScore` 가 true 면 숨김) |
| `OnboardingSwipe` | Figma `onboarding-swipe` | 워치 목업 + 워크아웃 지표 탭. 하단 3점 인디케이터가 보여야 스와이프가 설명된다 |
| `OnboardingComplication` | Figma `onboarding-complication` | 워치 목업 + 컴플리케이션이 올라간 문자판 |
| `OnboardingHealth` | 실기기 피트니스 앱 | 경기 저장 후 워크아웃 상세. 시스템 언어만 English 로 바꿔 한 벌 더 (**지역은 대한민국 유지** — 단위가 바뀐다) |
| `OnboardingShare` | 실기기 인스타그램 | 기록 상세 → **스티커로 복사** → 인스타 스토리 편집 화면에 붙인 상태. 공유 시트에서는 카드가 앱 아이콘 줄 위 썸네일로만 보여 무엇이 나오는지 안 보인다 |

Figma 파일은 `Apps` (`oK4L0L6xzNId7ASdQbX1Cu`), 페이지 `Ralli with Watch`. 기존 App Store 스크린샷용
워치 행 아래에 `onboarding-*` 프레임이 있다.

### 그림 규격

- **그림 자리는 코드가 고정한다.** `OnboardingScreenshotPage` 가 **비율 0.80 박스**를 잡고 그 안에서
  `scaledToFit` 하므로 그림 비율이 제각각이어도 페이지를 넘길 때 자리가 흔들리지 않는다. 남는 곳은
  검정 여백이 된다 (배경이 검정이라 보이지 않는다). 워치 3장은 Figma 프레임 비율 `422:514` 를 따른다
- **가로로 넓은 그림(워치)은 폭이 꽉 찬다** — 표시 폭 약 329pt 의 3배, **987px 이상**이 필요하다.
  **세로로 긴 그림(폰)** 은 높이 제한에 먼저 걸려 폭 약 190pt 로 들어가므로 **570px 이상**이면 된다
- **3x 로 내보낸다.** 에셋을 Single Scale 로 두므로 원본이 작으면 Retina 에서 흐려진다.
  표시 최대 크기가 약 345×420pt 이므로 **1035×1260px 이상**이면 충분하다
- 형식 PNG, 배경 검정 `#000000` (온보딩 배경과 같아 모서리 clip 이 드러나지 않는다)
- `OnboardingScreenshotPage` 가 `cornerRadius 24` 로 모서리를 깎는다 — 네 귀퉁이에 중요한 것을 두지 않는다

### 로컬라이즈

에셋 카탈로그의 **이미지 로컬라이즈**(ko/en)로 언어별 파일을 둔다. 코드는 이미지 이름 하나만 안다.

| 에셋 | ko/en 두 벌이 필요한가 |
|---|---|
| `OnboardingCrown` | **필요** — 화면에 "나"/"상대"(`ME`/`OPP`), "취소"(`Undo`) |
| `OnboardingSwipe` | **영어 한 장으로 통일.** `ACTIVE KCAL`/`TOTAL KCAL` 두 줄뿐이고 숫자와 하단 인디케이터가 주인공이라 감수했다 |
| `OnboardingComplication` | **한국어 한 장으로 간다.** 문자판의 날씨 컴플리케이션에 한국어가 박혀 있어(최고·최저, 지금·오후 N시) 영어 사용자도 한국어 문자판을 보게 되나, 이 페이지의 목적은 "문자판에 올려두면 한 번 탭으로 열린다" 이고 Ralli 아이콘 위치가 핵심이라 감수했다 |
| `OnboardingHealth` | **필요** — 피트니스 앱 UI 전체 |
| `OnboardingShare` | **필요** — 카드 안 문구(운동 시간·활동 킬로칼로리 등)와 인스타 UI |

**크라운 화살표와 라벨("내 점수"/"상대 점수", `ME`/`OPP`)은 이미지에 굽는다.** 처음에는 굽지 않고
`CrownArrowsOverlay` 가 런타임에 얹어 문자열 카탈로그로 로컬라이즈하려 했으나, Figma 에서 화살표·
회전(Rotate)·탭(Tap!) 그림을 직접 넣어 이미지 안에서 안내가 끝났다. 코드 오버레이를 그대로 두면
화살표가 두 벌로 겹쳐 손 그림을 가리므로 **오버레이와 `onboarding_crown_up`·`onboarding_crown_down`
키를 지웠다.** 이미지가 ko/en 으로 나뉘어 있어 언어별 라벨은 그림이 갖는다.

## 하지 않는 것

- 스와이프 카드에 일러스트 — 목업 합성으로 충분하고 디자인 작업이 별도로 붙는다
- 모드 옵션(No-Ad·타이브레이크) 설명 — 온보딩이 아니라 모드 선택 화면의 ⓘ 자리. 별도 작업
- 권한 프롬프트 선요청 — HealthKit 권한은 지금처럼 첫 경기 시작 때
- 애니메이션·인터랙션 — 정적 이미지. 나중에 원하면 1페이지만 크라운 회전 애니메이션으로 교체
- 워치 단독 시작 안내 — 워치 앱을 열면 버튼이 하나뿐이라 화면에서 발견된다
- `digitalcrown.*` SF Symbol — 목업에 크라운 실물이 있어 겹친다. Apple 하드웨어를 묘사하는 심볼이라
  사용 조건도 더 조심스럽다
