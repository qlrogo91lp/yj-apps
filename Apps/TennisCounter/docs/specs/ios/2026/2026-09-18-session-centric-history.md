# iOS 기록·요약 세션 중심 재편 설계

2026-09-18 확정. **[2026-08-25 요약·기록 리디자인](2026-08-25-summary-history-redesign-design.md)을 개정한다** —
그 문서의 기록 목록·상세 구조는 이 문서로 대체되고, 요약의 기간 필터·추이 차트는 항목만 바뀐다.

출발점은 1.1.8 TestFlight 실기기 메모(루트 `TODO.md` #9)와, 공유가 경기 단위로만 열린다는 발견이다.

## 목적

**세션(한 번의 워크아웃)을 앱의 1급 단위로 만든다.**

Ralli 는 한 워크아웃 안에서 경기를 여러 판 친다. 화면은 이미 세션으로 묶어 보여주는데
(`MatchSessionGroup`), 저장·공유·삭제는 모두 경기 단위다. 그 어긋남에서 문제가 나온다.

- 경기 상세에서 공유를 누르는데 **나가는 카드는 세션 누적값**이다. 중간 경기를 고르면 반쪽 값이 나간다
- 세션이 저장된 적이 없어 **"세션이 끝난 시점"이 데이터에 없다**. 마지막 경기 이후 구간이 샌다
- 네 지표 중 **심박만 경기 구간 평균**이고 나머지 셋은 세션 누적이다

### 왜 이렇게 됐나

저장 단위가 처음부터 경기였다. 공유 카드가 세션 값을 필요로 하자 새 모델을 만드는 대신
**경기 레코드에 누적값 컬럼을 덧붙이는 싼 길**을 택했고(`c5321c2`), `MatchSessionGroup` 은
그보다 나중에 **계산으로만** 들어왔다(`3ec1445`). 그 사이 중복 제거 키도 워크아웃에서
경기로 되돌린 이력이 있다(`66dc9d6`). 세션은 한 번도 저장된 적이 없다.

## 화면

### 기록 목록 — 세션 카드

경기 행을 없애고 **세션 카드만** 나열한다. 목록/캘린더 전환은 지금처럼 **툴바 아이콘 하나**다
(`calendar` ↔ `list.bullet`).

카드가 담는 것:

| 자리 | 내용 |
|---|---|
| 머리 | 날짜(요일) · `›` |
| 둘째 줄 | `3경기 · 2승 1패` — 경기가 없으면 `경기 없음` |
| 아래 | 운동 시간 · 활동 kcal · 평균 심박 |

**전적을 카드가 직접 보여줘야 한다.** 지금 `SessionHeader` 는 전적을 일부러 뺐는데
("아래 경기 행을 세면 나오는 값"), 경기 행이 사라지면 그 전제가 깨진다.

누적값이 없는 구버전 기록은 지표를 `–` 로 둔다 (0 으로 흘리지 않는다).

### 세션 상세 — 신규 화면

목록에서 **push** 로 연다. 진입점은 기록 탭 하나뿐이라 계층이 분명하고, 내용이 길어
시트의 당겨 닫기 제스처가 스크롤과 부딪히지 않는다.

```
‹ 기록                                  [공유]
9월 16일 (화)
오후 7:27 – 오후 10:03

┌ 운동 시간 25:23      활동 킬로칼로리 245 ┐
│ 총 킬로칼로리 303     평균 심박수 142    │   ← 공유 카드와 같은 구성·색
└──────────────────────────────────────┘

경기 3
┌ 1경기                 3세트 · 32분 ┐
│ 나      6  6                  ← 초록 │
│ 상대    4  3                  ← 주황 │
└──────────────────────────────────┘
(경기 2, 3 …)
```

- 지표 2×2 는 공유 카드와 같은 네 칸·같은 색(lime · amber · coral)으로 맞춘다
- **경기 상세 시트(`MatchDetailSheet`)는 이 화면에 흡수되고 사라진다.** 경기마다 별도 페이지를 두지 않는다
- 경기 카드는 `Scoreboard` 를 재사용한다

**스코어보드를 워치 점수 화면과 같은 색으로 맞춘다.** 지금은 이긴 행 전체를 굵게+흰색으로 그려
승패를 흡수하는데, 행마다 굵기가 달라 들쭉날쭉해 보인다. 대신 **굵기를 균일하게 두고
나는 초록(`.green`) · 상대는 주황(`.orange`)** 으로 가른다 — 워치 `PlayerPointButton` 이 쓰는
바로 그 색이라 앱 전체가 한 언어를 쓰게 된다.

**승패는 따로 적지 않는다.** 점수를 보면 읽히고, 위=나 / 아래=상대 위치도 워치와 같아서
색에만 기대지 않는다.

### 요약

기간 필터(주 · 월 · 전체)는 그대로 두고 **기간마다 보여줄 것을 다르게** 한다. 누적값은 `전체`
에서 의미를 잃는다 — "총 87시간"은 숫자만 크고 페이스가 안 읽힌다.

| 기간 | 공통 | 나머지 | 차트 |
|---|---|---|---|
| 이번 주 · 이번 달 | 경기 수 · 승률 | 총 운동 시간 · 총 활동 칼로리 | 세션별 운동 시간 추이 (지금 그대로) |
| **전체** | 경기 수 · 승률 | **운동한 세션 수 · 세션당 평균 시간** | **월별 세션 수** |

차트는 단일 계열이므로 범례를 두지 않고 축 라벨만 둔다. 숫자는 모든 막대에 붙이지 않고
최댓값 하나에만 붙인다.

**최근 세션은 1개.** 누르면 상세로 가지 않고 **기록 탭으로 전환**한다 — 그 세션이 목록 맨 위에
있기 때문이다. 기간 필터를 걸어도 "그 기간에서 가장 최근"은 전체에서도 가장 최근이라 어긋나지
않는다. 기록 탭이 캘린더 모드면 **목록 모드로 바꿔** 준다.

## 공유

**진입점을 세션 하나로 통일한다.**

| 위치 | 변경 |
|---|---|
| 세션 상세 머리 | **공유 버튼을 여기 둔다** |
| `MatchDetailSheet` | 화면째 사라진다 |
| `MatchResultView` (경기 결과) | **공유 버튼을 뺀다** |

카드 내용은 **지금 그대로** 둔다 — 운동 지표 네 칸, 스코어 없음. 따라서 **YJKit 은 고치지 않는다.**
`WorkoutShareCard` 의 2×2 는 지표 enum 으로 고정돼 있어 스코어를 넣으려면 Kit 설계를 바꿔야
하는데, 이번 범위가 아니다.

누르는 자리와 나가는 내용이 같아지므로 "중간 경기에서 반쪽 값이 나가는" 문제가 사라진다.
경기 결과 화면의 공유 버튼이 저장·다시하기 위에 떠 있어 거슬리던 것도 함께 해결된다.

## 삭제

**세션 단위만** 남긴다. 목록 카드를 스와이프해 세션을 통째로 지운다. 세부 경기를 따로 지울
일은 없다고 봤다.

`MatchPersistenceService` 의 중복 제거 키는 지금처럼 **경기 단위(`matchId`)를 유지**한다 —
과거에 워크아웃을 키로 썼다가 같은 워크아웃의 다른 경기까지 지워지는 버그가 있었다(`66dc9d6`).
삭제 **단위**가 세션이 되는 것과 중복 제거 **키**는 별개다.

## 데이터 — `WorkoutSessionRecord` 신설

운동을 끝낼 때 세션 레코드를 하나 남긴다. 지금은 최종값이 계산되고도 버려진다.

```swift
Task { _ = await healthKit.stopWorkout() }   // WorkoutResult? 를 버린다
```

`stopWorkout()` 은 이미 `WorkoutResult?` 를 public 으로 돌려주며 그 안에 워크아웃 **전체**
평균 심박(`builder.statistics(...).averageQuantity()`)과 최종 시간·활동/총 칼로리가 들어 있다.
**YJKit 수정은 필요 없다** — 앱이 받지 않고 있을 뿐이다.

| 필드 | 내용 |
|---|---|
| `workoutSessionId` | `Match.workoutSessionId` 와 잇는 키 |
| `startedAt` / `endedAt` | 워크아웃 시작·종료 |
| `elapsedSeconds` | 최종 경과 시간 |
| `activeCalories` / `totalCalories` | 최종 칼로리 |
| `averageHeartRate` | **워크아웃 전체 평균** |
| `healthKitUUID` | 건강 앱 기록과 잇는 키 |

CloudKit 요구사항에 따라 **모든 속성은 optional 또는 기본값**을 갖는다.

**흐름** — 워치가 `stopWorkout()` 결과를 받아 기존 `sendWorkoutEnd` 에 실어 보내고, iOS 가 저장한다.
경기 저장(저장 버튼)과는 **독립**이다. 경기 저장 흐름은 건드리지 않는다.

**집계 우선순위** — `MatchSessionGroup` 은 레코드가 있으면 그 값을 쓰고, 없으면(구버전 기록)
지금처럼 경기들의 최댓값으로 폴백한다. 심박은 폴백할 값이 없으므로 `–` 로 둔다.

이로써 **마지막 경기 이후 구간이 새는 문제**와 **심박만 성격이 다른 문제**가 함께 풀린다.

### 경기 없는 세션

경기를 한 판도 저장하지 않은 세션도 레코드가 남으므로 **기록에 띄운다.** 연습이나 랠리만 하고
점수를 안 센 날도 "2시간 쳤다"가 남는다. 카드 둘째 줄은 `경기 없음`, 세션 상세에는 지표만
보이고 경기 목록이 비어 있다. 요약의 "운동한 세션 수"와도 숫자가 맞아떨어진다.

## 하지 않는 것

- **공유 카드에 스코어 넣기** — Kit 설계를 바꿔야 한다. 이번 범위 밖
- **심박 그래프** — HealthKit 샘플 조회는 권한·동기화 지연 문제가 따로 있다 (`TODO` 에서 이미 분리)
- **경기 단위 삭제** — 세션 단위로 충분하다고 봤다
- **경기별 심박 제거** — `Match.averageHeartRate` 는 그대로 두고 세션 상세의 경기 카드에서 쓸 수 있다
- **캘린더 자체 개편** — 하단 목록이 세션 카드로 바뀌는 영향만 받는다

## 열린 질문

- **CloudKit 스키마 배포** — 새 엔티티는 배포 후에야 동기화가 붙는다. 기존 기기의 기록과 섞일 때
  폴백이 제대로 도는지 실기기에서 확인해야 한다
- **세션 카드의 심박 칸** — 세션 레코드가 생긴 뒤에야 값이 찬다. 구버전 기록은 계속 `–` 다
