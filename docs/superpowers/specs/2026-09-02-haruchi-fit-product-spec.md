## 1. 제품 정의

하루치 시리즈의 네 번째 앱. **"운동하면 잔디가 자란다"** 한 문장이 제품 전체다.

GitHub 잔디의 동기 부여 구조를 운동 기록에 옮긴 것으로, 사용자는 애플워치로 운동을 시작하고
폰은 열지 않아도 잔디가 채워진다. 폰은 감상·보강·공유를 위해 나중에 여는 도구다.

### 차별점

시중 운동 앱과 다른 유일한 지점은 **한 세션 안의 근력↔유산소 전환을 세그먼트로 기록**한다는 것이다.
"오늘 웨이트 54분 + 러닝 18분"이 한 워크아웃 안에서 구분되어 남는다. 이 값이 홈의 비율 바,
기록 상세의 타임라인, 워치 요약의 세그먼트 바, 통계의 근력·유산소 차트를 전부 먹인다.

세그먼트가 없으면 이 앱은 "잔디 달린 운동 기록 앱"에 그친다. **세그먼트 UI는 어느 화면에서도 생략하지 않는다.**

### 대상 사용자

주 2~4회 헬스장에 가는 캐주얼 사용자. 세트·무게·1RM을 기록하는 하드코어 리프터가 아니다.
이 구분이 아래 비목표 전부의 근거다.

## 2. 목표와 비목표

### 목표

- 애플워치만으로 기록이 완결된다. **폰을 한 번도 열지 않아도 잔디가 찬다.**
- 근력↔유산소 전환이 운동 중 **1탭 + 햅틱**으로 끝난다.
- 워치가 없거나 HealthKit을 거부해도 앱이 온전히 동작한다 (수동 기록 모드).
- 과거 잔디가 **영구 보관**된다 — 성취 자산이므로 연 단위로 사라지지 않는다.

### 비목표 (v1 스코프 밖)

| 항목 | 이유 |
|---|---|
| 세트·무게·횟수 기록 | 대상 사용자가 캐주얼. 입력 비용이 앱 이탈의 1순위 원인 |
| 운동명 라이브러리 | v2. v1에서는 **메모가 대신**한다 |
| 칼로리 추이·심박존 등 강도형 지표 | 다이어트 앱 인상 + 건강 앱과 중복 (6절 D5) |
| 소셜·팔로우·랭킹 | 공유는 인스타그램 스토리 내보내기로 충분 |
| 개인 퍼센타일 기반 잔디 농도 | v1.1. v1은 고정 컷 (6절 D4) |

## 3. 정보 구조

### 탭 3개 — 역할 원칙

| 탭 | 역할 | 차트 |
|---|---|---|
| **홈** | 감상 | 비율 바 1개만 (유일한 예외) |
| **기록** | 관리 — 개별 기록의 열람·편집 | 없음 |
| **통계** | 분석·아카이브 | 전부 여기 |

**차트는 통계 전용이다.** 홈의 주간 비율 바 하나만 예외로 허용한다.
이 원칙이 깨지면 홈이 대시보드가 아니라 분석 화면이 되어 "감상" 역할을 잃는다.

**설정은 탭이 아니다.** 홈 좌상단 ⚙ 아이콘으로 진입한다 — 탭 하나를 설정에 쓸 만큼
자주 여는 화면이 아니다.

### 화면 목록 (iOS 11 + watchOS 3 + 컴플리케이션)

```
01a 온보딩 1 — 컨셉          05  통계
01b 온보딩 2 — 권한          06  공유
02  홈                        07  설정
03a 기록 — 달력               08  수동 기록 추가
03b 기록 — 목록
04a 기록 상세 (태깅됨)        W0  워치 홈
04b 기록 상세 (태깅 전)       W1  워치 세션 (a 지표 / b 컨트롤 — 페이징)
                              W2  워치 요약
                              WC  컴플리케이션
```

## 4. iOS 화면

### 02 홈 — 대시보드

상단 바: 좌 ⚙ 설정 · 중앙 `8월 2026` · 우 `+` 수동 추가

1. **잔디 히어로** — 최근 약 4개월(17주 × 7일), 좌우 스와이프. 오늘 칸은 **펄스 애니메이션**.
2. **축적 스탯 2개** — `이번 달` / `전체 누적`. 세로 구분선으로 분리.
3. **이번 주 운동 구성 바** — 우측에 주간 총시간. 아래 범례 `근력 4.2h` / `유산소 2.0h`.
4. **최근 기록 2개** — 헤더 우측 `전체 보기 ›` → 기록 탭. 각 행은 날짜·시간대, 세그먼트 칩, 부위 칩, 우측 kcal.

**엠프티 스테이트** — 기록 3회 미만이면 비율 바 자리에 **마일스톤 한 줄**로 대체한다.
데이터 3개로 그린 비율 바는 정보가 아니라 노이즈다.

> **"올해 누적" 기각** — 연 단위로 리셋되는 숫자는 축적의 감각을 깨뜨린다.
> 1월 1일에 0으로 돌아가는 스탯을 홈 히어로 옆에 두면 오히려 동기를 꺾는다.
> 연 단위 숫자가 필요하면 통계 탭에 있다.

### 03a 기록 — 달력

`[달력] ↔ [목록]` 세그먼트 토글이 상단에 있다. **Ralli 기록 탭의 패턴을 그대로 재활용**한다.

- 월 이동 행: `‹ 2026년 8월 ›` + 우측 월 요약 `12회 · 9.2시간`
- 월 그리드. 날짜 칸의 농도는 **잔디와 완전히 동일한 규칙**을 쓴다 (6절 D4)
- 날짜 탭 → 기록 상세 하프 시트

### 03b 기록 — 목록

- 최신순, **주 단위 섹션** (`이번 주` / `지난 주` / …)
- 각 행: 날짜 `8월 22일 (토)` + 세그먼트·부위 칩 + 우측 kcal
- **스와이프 삭제** 지원
- 아이템 탭 → 기록 상세 하프 시트

기록 탭에는 **집계도 차트도 없다.** 개별 기록의 열람과 편집 전용이다.

### 04 기록 상세 — 하프 시트

**풀 페이지가 아니라 하프 시트다.** 세트 데이터가 없어 내용이 적기 때문에 풀 페이지는 빈 화면이 된다.

구성 (위에서 아래로):
1. 그랩 핸들
2. 헤더 — `8월 22일 (토)` / `저녁 7:12 – 8:24`, 우측 `↑` 공유 버튼
3. 요약 3칸 — `72분` 총 시간 / `412` kcal / `128` 평균 심박
4. **운동 구성** — 세그먼트 타임라인 바 + 아래 텍스트 `근력 54분 · 유산소 18분`
5. 구분선
6. **부위** — 칩 6개, 탭 = 토글, **저장 자동**
7. 메모 — 비어 있으면 `메모 추가하기…` 플레이스홀더
8. 액션 — `삭제` / `편집` / `공유`(주)

**두 케이스 모두 같은 레이아웃이다:**

| | 04a 근력+유산소·태깅됨 | 04b 유산소만·태깅 전 |
|---|---|---|
| 타임라인 | 3구간 (오렌지-블루-오렌지) | 1구간 (블루 100%) |
| 부위 칩 | `가슴`·`팔` 선택됨 | 전부 미선택 |
| 메모 | `벤치프레스 5×5, 딥스` | 플레이스홀더 |

> **부위 섹션은 유산소 전용 세션에서도 항상 표시한다** (조건부 숨김 폐기).
> 이 앱은 근력 중심이고, 세그먼트가 잘못 분류됐을 때 사후 보정할 여지도 확보된다.
> **빈 상태가 정상이며 태깅을 유도하는 CTA는 두지 않는다.**

### 05 통계 — 연도 아카이브

상단 연도 세그먼트 `2026 · 2025 · 2024`. **연도를 바꾸면 잔디·요약·차트가 전부 교체**된다.
첫 해에는 2026만 표시한다.

스크롤 순서:
1. **그 해 풀 1년 잔디** (53주 × 7일) + 아래 월 눈금 `1 · 4 · 7 · 10 · 12월`
2. **연 요약 3칸** — `142회` 올해 운동 / `118시간` 올해 누적 / `주 3.4회` 평균
3. **월별** — 12막대. 미래 월은 흐리게(opacity 0.3)
4. **근력 · 유산소** — 비율 바 + 범례 `근력 75.5h (64%)` / `유산소 42.5h (36%)`
5. **요일 패턴** — 7막대, 상위 요일 강조
6. **부위** — 가로 막대, 세션 수 내림차순. **태그가 0건이면 섹션 자체를 숨긴다**
7. **마일스톤 배지** — 달성분 + 잠긴 다음 목표 (`🔒 200회 · 58 남음`)

> 부위 섹션의 숨김 규칙은 04 기록 상세의 "항상 표시"와 **모순이 아니다.**
> 상세는 입력 수단이라 항상 열려 있어야 하고, 통계는 결과 표현이라 데이터가 없으면 뺀다.

> **요일별 분포는 저평가된 지표다.** "나는 월수금형"이라는 자기 인식을 주고,
> 2주치 데이터만으로도 의미 있게 동작한다.

### 06 공유

> ⚠️ **목업 06(잔디 카드)은 채택하지 않는다.** YJKit에 이미 있는 `WorkoutShareUI`를 그대로 쓴다.
> 결정 근거는 아키텍처 문서 D-M2.

- 카드 내용은 **패키지가 소유한다** — 시간 · kcal · 평균 심박 최대 3행.
  값이 없는 지표는 `--`가 아니라 **행 자체가 빠진다**
- **톤 선택 UI 없음.** 배경은 브랜드 오렌지에서 파생된 그라디언트 하나로 고정
- 인스타그램이 설치돼 있으면 스토리 편집기가 열리고, 카드는 **스티커**로 올라가
  사용자가 자기 사진·영상 위에 끌어 배치할 수 있다. 없으면 1080×1920 이미지로 공유 시트 폴백
- 진입: **기록 상세의 `↑`** 와 워크아웃 결과

목업에 있던 잔디 그리드 카드, `8월, 12번째 운동` 문구, 톤 3종(다크/라이트/오렌지),
`이미지 저장` 버튼은 **v1에 없다.**

### 07 설정

| 그룹 | 항목 |
|---|---|
| 잔디 | 진하기 기준 → `운동 시간` ↔ `칼로리` |
| 연동 | 건강 앱 `연결됨` / 앱 소개 다시 보기 |
| **하루치 시리즈** | 하루치 — 시간 기록 / Ralli — 테니스 / GolfCounter — 골프 |
| 정보 | 개인정보처리방침 / 문의하기 |

하단에 버전 표기. 크로스 프로모션을 개별 앱 나열이 아니라 **"하루치 시리즈"라는 브랜드 레벨**로 노출한다.

### 08 수동 기록 추가

**필수 입력은 `언제`와 `얼마나` 둘뿐이다. 30초 안에 끝나야 한다.**

- 언제 — 날짜·시각
- 얼마나 — 운동 시간
- 유형 — `근력` / `유산소` **단일 선택** (세그먼트 분할 입력은 v1 미지원)
- 부위 — 칩 6개 (선택)
- 메모 (선택)

용도: 워치 없이 운동한 날, HealthKit 누락 보정.

### 01 온보딩 (2장)

1. **컨셉** — 잔디가 채워지는 애니메이션 + `운동하면 / 잔디가 자랍니다`.
   워치 안내 한 줄을 여기에 흡수했다
2. **권한** — HealthKit 요청. `연결하기` + **`나중에 · 직접 기록할게요`**

**거부해도 진행 가능하다** — 수동 기록 모드로 앱이 완결된다.

## 5. watchOS 화면

GolfCounter / Ralli 실제 화면에서 디자인 언어를 추출해 통일했다. **기존 4화면에서 유형 선택 화면을 제거해 3화면.**

### 디자인 언어

- 버튼: 캡슐형(r ≈ 22–26), 틴트 배경 + 밝은 텍스트, SF Symbols 아이콘 동반
- 요약 화면: 큰 숫자 중심 + 회색 캡션 + 가로 2버튼 (버리기 회색 / 저장 브랜드색)
- 홈: 브랜드색 앱 이름 + 큰 캡슐 CTA + 작은 설정 행 (라벨 + 값 pill)
- 색 대응: 골프 그린 → **하루치 오렌지**, 일시정지 노랑 · 종료 빨강 유지, 유산소 = 블루

### W0 홈

```
Haruchi Fit          ← 오렌지
[   운동 시작   ]    ← 캡슐 CTA
시작 운동    ( 근력 )  ← 토글 행
```

- **유형 선택 화면을 토글로 흡수했다.** 탭하면 근력↔유산소 순환 — 2개뿐이라 피커가 불필요하고,
  화살표 아이콘도 두지 않는다
- **CTA 색은 오렌지 고정.** 유형별로 색을 바꾸지 않는다. 유형 구분은 토글 텍스트 색으로만
- 마지막 선택을 기억하므로 **실사용은 대부분 1탭**

### W1 세션 (페이징 2장)

**W1a 지표** — 기존 워크아웃 화면을 그대로 쓴다. 상단에 현재 모드 라벨(`진행 중 · 근력`) 한 줄만 추가.

**W1b 컨트롤** — 기존 일시정지/종료 캡슐 세로 스택을 **그대로 유지**하고, 그 위에 전환 행만 추가.

```
[ 근력 ] [ 유산소 ]   ← 추가되는 행. 활성 = 채운 배경 / 비활성 = 틴트
[ ❚❚ 일시정지     ]   ← 기존
[ ■  운동 종료    ]   ← 기존. 맨 아래 = 오조작 방지
```

> **2×2 그리드 안은 기각** — 기존 두 앱의 컨트롤 구조와 불일치해 시리즈 일관성을 깬다.

### W2 요약

```
      운동 완료          ← 오렌지 타이틀, 상단 중앙
      1:12:24            ← 큰 시간 (1시간 미만은 54:12로 축약)
  ███████▒▒▒███          ← 세그먼트 바 (필수)
  근력 54분   유산소 18분
  ♥ 128      🔥 412
  [ 버리기 ] [ 저장 ]
```

- **세그먼트 바는 필수다** — 이 앱의 유일한 기능적 차별점을 시각화하는 요소
- 2×2는 **배경 카드 없이 텍스트만** — 기존 UI 밀도 유지
- **버리기 탭 시 확인 1단계 필수** (되돌릴 수 없음). 폐기하면 HealthKit에도 저장하지 않는다

> **"버리기" 용어 확정** — GolfCounter가 이미 쓰고 있어 시리즈 일관성을 우선했다.
> `저장 안 함`(길고 '저장'과 혼동), `폐기`(딱딱함) 기각.

### WC 컴플리케이션

**GolfCounter · Ralli와 같은 방식이다.** 진행 중인 워크아웃 세션 상태만 보여주고,
**누적 기록이나 잔디는 표시하지 않는다.**

| 상태 | 표시 |
|---|---|
| 세션 없음 | 앱 아이콘 + `운동 시작` — 앱 실행 진입점 역할 |
| 세션 진행 중 | 경과시간 + 현재 모드(근력/유산소), 배경을 활성 색으로 |

- 패밀리 3종: `accessoryCircular` · `accessoryCorner` · `accessoryRectangular`
- 세션이 없을 때는 **시간 기반 갱신을 하지 않는다**(`.never`). 상태가 바뀌면 워치 앱이
  `reloadAllTimelines()`를 호출한다
- 오늘 운동 여부·이번 달 횟수 같은 **집계 값을 넣지 않는다** — 그러려면 앱을 안 열어도
  HealthKit이 갱신돼야 하는데, 그 비용을 v1에서 지지 않기로 했다 (아키텍처 D-M4)

### 햅틱

watchOS 커스텀 버튼은 **햅틱이 자동으로 나지 않는다.** 직접 지정해야 한다.
운동 중에는 화면을 계속 볼 수 없어 **촉각이 유일한 확인 수단**이므로 필수 구현이다.

| 동작 | 햅틱 | 이유 |
|---|---|---|
| 세션 시작 | `.start` | 의미론적 일치 |
| 근력 → 유산소 | `.directionUp` | 눈 없이 방향 구분 |
| 유산소 → 근력 | `.directionDown` | 위와 대칭 |
| 유형 토글 (W0) | `.click` | 가벼운 확인 |
| 일시정지 / 재개 | `.click` | 가벼운 확인 |
| 운동 종료 | `.stop` | 세션 종료 신호 |
| 저장 완료 | `.success` | 완료 피드백 |
| 버리기 확정 | `.failure` | 파기 경고 |

구현: `WKInterfaceDevice.current().play(.click)` 또는 watchOS 10+ `.sensoryFeedback(.selection, trigger: currentMode)`

> ⚠️ **시뮬레이터에서 재현되지 않는다 — 실기기 테스트가 반드시 필요하다.**

## 6. 확정 규칙

### D1. 부위 태깅

- **부위 6개**: 가슴 · 등 · 어깨 · 팔 · 하체 · 코어
  - 유산소는 세그먼트로 이미 기록되므로 부위 목록에서 **제외**한다
- **멀티 선택** — "가슴+삼두", "등+이두" 조합이 일반적이라 단일 선택은 현실과 맞지 않는다.
  칩 탭 = 토글, 저장 자동
- **태그 단위는 세션** — 세그먼트별로 쪼개지 않는다. 근력+유산소가 섞인 세션에서
  부위 태그는 근력 부분을 가리키는 것으로 자연스럽게 읽힌다
- **부위 섹션은 기록 상세에서 항상 표시** (5절 04 참조)

### D2. 통계 집계 = 세션 카운트

`하체 18` = 하체를 태그한 **세션 18건**이다.
한 세션에 2부위를 태그하면 각각 +1 되므로, **부위 카운트 합계가 총 운동 횟수보다 클 수 있다.**
비율이 아니라 빈도이므로 정상이다.

### D3. 잔디 칸 = 하루 1개

하루에 2세션을 해도 **잔디 칸은 1개**다. 두 세션의 시간이 **합산**되어 농도를 결정한다.

### D4. 잔디 농도

- **단색 오렌지 4단계.** 색상환을 쓰지 않는다
- 기준은 **운동 시간(기본) ↔ 칼로리** — 설정에서 전환
- **v1은 고정 컷.** 개인 퍼센타일 기반은 v1.1로 미룬다
- **수동 기록**(HealthKit 값 없음)은 **최소 농도 fallback**
- 기록 탭 달력의 날짜 농도도 **같은 규칙**을 쓴다

**시간 기준 컷 (하루 합산)**

| 단계 | 범위 |
|---|---|
| 1 | ~30분 |
| 2 | 30~60분 |
| 3 | 60~90분 |
| 4 | 90분 초과 |

주 2~4회 헬스장에 가는 대상 사용자의 한 세션이 보통 60~90분이므로 **2~3단계가 기본값**이 된다.
칼로리 기준 컷은 구현 시점에 실제 데이터를 보고 정한다.

### D5. 지표 선정 원칙

| 유형 | 예 | 배치 |
|---|---|---|
| 축적형 | 누적 횟수·시간 | **홈** |
| 리듬형 | 요일별·월별 | **통계** |
| 구성형 | 근력/유산소 비율·부위 | **통계** (비율 바만 홈 예외) |
| 강도형 | 칼로리 추이·심박존 | **쓰지 않음** |

강도형을 뺀 이유: 다이어트 앱 인상을 주고, 애플 건강 앱과 중복된다.

### D6. 메모는 부위와 독립

v1에서는 운동명을 적고 싶을 때 **메모가 대신**한다. v2에서 운동명 라이브러리를 도입할 때 분리한다.

### D7. 전환 횟수는 표시하지 않는다

"3회 전환" 같은 숫자는 잔여 데이터로 정보 가치가 없다. 세그먼트 **바**로만 보여준다.

## 7. 디자인 토큰

목업 `:root`에서 추출. 다크 기준이다.

| 토큰 | 값 | 용도 |
|---|---|---|
| `accent` | `#FF9500` | 브랜드 · **근력** · 잔디 |
| `cardio` | `#8CB4E8` | **유산소** |
| `hr` | `#FF453A` | 심박 |
| `bg` | `#1C1C18` | 배경 |
| `surface` / `surface-2` / `surface-3` | `#252521` / `#2C2C27` / `#35352E` | 카드 계층 |
| `line` | `#33332C` | 구분선 |
| `text` / `dim` / `faint` | `#F2F0EA` / `#8E8C82` / `#5C5B53` | 텍스트 3단계 |
| `cell` | `#28281F` | 잔디 빈 칸 |

브랜드색은 **시스템 오렌지**(`#FF9500`)다. 배경은 순수 검정이 아니라 **따뜻한 뉴트럴**(`#1C1C18`) —
잔디 오렌지와 어울리게 하기 위해서다.

> ⚠️ 기존 `WorkoutUI` 워치 화면은 경과시간을 **노랑**(`.yellow`)으로 그린다.
> 하루치 핏 목업은 오렌지 계열이므로 색 처리 방침이 필요하다 — 아키텍처 문서 미결 항목.

## 8. 핵심 흐름

### A. 기본 기록 (해피패스) — 폰을 한 번도 안 열어도 완결

```
W0 운동 시작 → W1 세션 → 전환 1탭(햅틱) → W2 저장
             → HealthKit + SwiftData → 홈 잔디 자동 반영
```

### B. 보강 (선택)

```
홈 최근 기록 / 기록 탭 → 하프 시트 → 부위 토글 · 메모 → 닫기 (자동 저장)
```

### C. 워치 없이 (fallback)

```
기본 운동 앱 → HealthKit import → 자동 표시
또는  [+] → 수동 추가
```

### D. 공유

```
기록 상세 [↑] → 공유 카드(시간·kcal·심박) → Instagram 스토리 (없으면 공유 시트)
```

> 목업의 "홈 잔디 길게 누르기" 진입은 **삭제**했다 — 카드가 잔디 아트워크가 아니게 됐으므로
> 잔디에서 진입할 이유가 없다.

| 용어 | 뜻 | 쓰지 않는 말 |
